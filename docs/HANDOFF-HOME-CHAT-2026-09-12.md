## 4. Nuxt 页面与交互清单

### 首页

- 黑色画布、灰色侧栏、明显更浅的灰色卡片／页脚、大圆角、精致铜橘按钮和彩色统一风格图标；精确色值参考首页文档建议，按浏览器效果校准。
- 人物背景按最新九尾方向参考原妲己身份，保持文本可读；新背景素材未定稿，不能把生成图裁切人物当成已确认母版。
- 输入框外为图片／视频创作切换；框内提供文字、`@`、按能力显示的上传区域、模型与必要参数、费用和发送操作。
- 去掉重复的加号、图片／视频附件按钮、角色附件按钮；`@` 负责已有引用，上传框负责新文件。
- 首页向对话页传递描述、模式、已选模型、参数、引用及真实文件／已上传资产 ID；跳转本身不产生第二次任务。
- 全部工具有限展示，最近创作有限展示，探索按批追加。分类切换重置分页，失败可重试，无更多时显示结束态。
- 媒体框统一为横版 16:9、竖版 9:16；保留原文件比例。列表封面可裁切，完整预览不裁主体、不拉伸。
- 卡片悬停有描边与内部图片放大，外框不变；热门／最新在右上角，操作蒙版渐显。手机端有可触达的等价操作。
- 登录／注册入口与头像菜单区分状态；未登录生成／发布弹出登录，保留草稿，登录后回到费用确认，不自动扣费。

### 对话创作页

- 桌面：历史会话侧栏、中间消息和输入区、右侧按需展开的产物预览。沿用 `/create` 为入口，会话定位方式可用查询参数等现有兼容方案。
- 历史：搜索、时间分组、新建、重命名、切换、归档；服务端目前是归档，不要伪装成物理删除。删除语义另行确认，不能级联删除资产。
- 消息：用户文本／素材、助手反馈、任务引用分开建模；排队、执行、完成、失败、取消状态属于任务卡。
- 图片／视频生成时允许继续发送普通消息和新的需求；不能因为存在 running 任务禁用整个输入框。
- 多结果属于同一任务组，每个资产可独立选中和预览；不能只保留第一张。
- 单击结果只预览。“继续修改”或“生成视频”才显式设置下一步对象；输入区持续显示引用及用途：参考图、首帧或当前修改对象。
- 图片预览：缩放、切换同组图片、下载、继续修改、生成视频、适用工具；更多菜单承载保存角色／发布。
- 视频预览：封面、真实播放控件、进度拖动、声音、全屏、下载与适用操作；尚未完成时不渲染虚假视频 URL。
- 修改产生新版本，旧结果保留。只有“保存／更新角色”主动操作才影响角色资产。
- 普通“进度怎么样”消息不能被当作图片／视频提示词提交生成；模糊的修改对象需澄清，不能猜选第一张。
- 草稿按用户和会话隔离；刷新后恢复可恢复的参数和资产引用。本地 File 对象不能假装能跨刷新恢复，需明确上传状态与重新选择提示。

### 模型选择与参数

模型卡显示名称、后台提供的用途介绍、示例、能力标签和起步价格；选择参数后显示本次准确费用。筛选可用搜索、图片／视频能力、参考图支持、时长、清晰度等，不出现渠道术语。

基础参数：图片尺寸／画幅和数量，视频时长／分辨率／画幅。高级参数只有当前模型支持时显示，例如种子、Steps、CFG、采样器、LoRA。组合是否合法由 Go 校验，不能把所有字段笛卡尔积当作可用组合。

### 移动端

- 单列会话；历史侧滑抽屉；模型与参数底部面板；产物全屏预览。
- 输入区随软键盘保持可用，避开安全区；长模型名称不挤掉发送按钮。
- 顶部显示任务概况，消息流内展示具体任务。新事件不强迫正在翻历史的用户跳到底部，提供新消息提示。
- `@` 选择、菜单、蒙版等有触摸入口；底部面板可滚动、可关闭并保留选择。
- 协议链接在导航抽屉／账户的稳定位置，不在无限信息流底端。

## 6. Go 工作清单

### G1. 用户模型目录与运营文案

在现有 catalog/model 边界增加统一用户视图，保留旧客户端兼容。由后台配置模型展示名、简短用途、示例、能力与排序；不要在 Nuxt 硬编码“模型 A 适合什么”。查清现有模型元数据与运营配置后选择扩展位置，不先建平行模型系统。

建议新增用户视图字段（概念草案，非现有契约）：`id`、`displayName`、`summary`、`examples`、`capabilities`、`inputRules`、`parameterSchema`、`pricingSummary`、`available`、`unavailableReason`。实际 endpoint 优先增量扩展 `/platform/catalog`，不强制采用这些命名。

同模型若有不同价／不同能力版本，提供可理解的版本差异和稳定选择 ID；后台选路不能改变用户确认的能力与收费。运行渠道、内部 workflow 和文件名不用出现在新版 UI。

### G2. 报价与生成前确认

从既有计费内核抽取可复用的只读报价，返回金额、单位、参数依据和版本／有效期等必要信息。提交时重新校验；参数或价格变化先回到确认，不按过期价格悄悄扣更多钱。

现有 task service 区分 credit 预占与 cloud balance 扣款，**不是统一一种积分**。本轮保留账务语义，用户价格必须有正确单位，不能把余额金额简单标成积分。统一货币若需改动须另行决策。

### G3. 两层防重与再次生成

第一层为传输幂等：同一逻辑提交的连点、重发和网络恢复使用相同 clientKey，返回原任务；同键不同内容应冲突。客户端不能每次网络重试都生成新键。需要验证并发竞态，依靠事务／唯一约束等保证只产生一次任务和一次计费。

第二层为用户再次发送同内容：服务端判断相同会话中的生成意图，未确认前返回原任务与重复提示，**不创建、不预占、不扣款**。确认弹窗显示现有任务状态、再次生成的费用影响，并提供“查看已有任务”“仍要再次生成”。

建议比较：站点、用户、产品、会话、任务类型、模型／版本、提示词、负面词、实际生效参数、角色引用版本与有序参考素材。比较用户选择的随机种子意图，不让运行时新派生的随机 seed 绕过重复判断；确认后再次生成随机种子是合法的新任务。

建议确认凭据绑定用户、规范化请求、已有任务和报价版本，短时有效；再次生成使用新 clientKey，确认请求重试则复用该新 key。不要仅接受任意 `force=true` 就绕过全部校验。具体字段、过期规则和错误码落地前更新契约。

检测与创建必须避免并发穿透；事务内完成必要检查，并保证提示路径没有资金变动。相同请求已完成、处理中、失败的提示可不同。判重历史窗口尚未确定，建议以当前会话有效记录为初期边界，明确记录最终选择，不做跨用户相似语义搜索。

### G4. 对话消息、任务意图和历史

现有 generation_session 可复用，但需要持久化普通用户／助手消息、结构化素材引用、任务关联与当前生成对象。使用字符串 ID，消息和任务生命周期分离。普通文字问答不能强制创建计费任务。

新增薄的后宫对话应用层，负责理解／澄清需求、返回状态回复、准备生成意图；执行继续调用 platform/task。不要把角色扮演聊天系统直接套到生产会话，也不需要为首版引入通用 Agent 平台。

消息提交响应至少能区分“普通回复”“需澄清”“待报价／确认”“重复待确认”“任务已创建”。生成动作走确认后的现有内核。具体消息 endpoint 和 schema 为待新增契约，不能声称 `/platform/session` 已提供这些行为。

显式传入／校验会话 ID，任务必须归属用户正在使用的会话；多标签页不能依赖一个全局 active 会话猜归属。分页读完整历史、多产物及活动任务，避免一次只取 30 条形成假完整历史。

### G5. SSE 与恢复

复用 `/platform/events` 及现有事件：`task.queued`、`task.started`、`task.progress`、`task.completed`、`task.failed`、`task.cancelled`。按 taskId 更新唯一任务实体，再投影到消息卡、历史侧栏和全局状态。

刷新先读权威任务状态再续订，重连去重和补齐。无真实进度只显示阶段与已等待时间，不编造队列位置或预计结束时间；断线不等于任务失败。轮询可保留作兜底，不能成为新的自动生成请求。

取消能力按实际执行器返回；不能 UI 点击即标记已取消。公共 SSE／任务改动保持对 gamelora 兼容。新普通消息若需流式回复，其事件契约与任务事件区分，不让增量文本触发生成。

### G6. 素材、产物与账户

复用素材存储、资产下载和账号能力。历史读取按资产 ID 获取可用展示地址，多产物全量返回，过期 URL 可刷新。角色引用带可追溯版本，不因修改图片自动覆盖角色。

首期下载与预览真实接通，完整发布／角色管理扩展可 mock；mock 不得混入真实个人资产或真实发布记录。

## 7. Nuxt 拆分建议与最小实施顺序

保留 Nuxt 4、Nuxt UI、现有编辑器与请求封装。按实际职责提取会话历史、输入器、模型选择器、动态参数、任务卡、产物预览、重复确认与登录弹窗；不要同时重写全部 composables 或更换 UI 框架。

任务状态与当前页面展示分离，不能每次切会话丢失活动任务。明确区分 messageId、clientKey、taskId、assetId，不再用大整数转 Number 充当所有 UI 主键。

建议执行顺序：

1. 记录工作区现状，确认本次差异；更新必要接口草案和模型用户视图。
2. 首页、对话桌面／移动端搭建，其他模块显式 mock，核心请求保留真实适配入口。
3. 接通模型介绍／能力／报价和上传，验证首页草稿进入正确会话且不重复发送。
4. 接通真实消息、显式会话归属、生成／防重确认／计费，再接 SSE 与恢复。
5. 接通全量产物、预览、下载、图片转首帧视频与历史继续创作。
6. 做移动端与异常验收，记录仍 mock 的入口，不以演示图替代真实链路验证。

首条验收流程：描述或上传 → 选择模型并确认费用 → 生成图片 → 选定结果作为首帧 → 生成视频 → 等待期间问进度 → 收到真实 SSE → 预览／下载 → 刷新并继续历史。

## 8. 测试与交付标准

- Nuxt：按 package.json 执行 typecheck、受影响文件 lint、build。浏览器覆盖桌面、390px 与 320px 窄屏，检查无横向溢出、键盘不遮发送、弹层可关闭、图片／视频不拉伸。
- Go：对修改的 catalog、session、task、billing 边界运行有意义的单元／集成测试；沿用现有测试数据库约定，不使用生产账本做测试。
- 请求幂等：并发同 key 只创建一次；同 key 不同内容冲突；网络超时重试找回原任务。
- 重复内容：不同 key 同内容先提示且不扣款；取消确认不扣款；确认后仅新建一次；确认重发、参数变化、报价过期均有确定行为。
- 对话：问进度不创建任务；生成期间可继续发送；切会话后新任务归属正确；所有任务／消息按用户和站点隔离。
- SSE：断线恢复、重复事件、先收到完成事件再收到创建响应等时序不产生重复卡片；刷新后排队／运行不能被显示为 cancelled。
- 历史与产物：多结果完整，草稿按会话隔离，引用原图可追溯，过期展示 URL 可恢复。
- 模型：介绍来自后台，价格单位正确，模型不支持的参数和引用无法通过 UI 或 API 绕过。
- mock：只有显式演示模式使用，关闭 mock 后不得出现假发布／假产物；核心失败明确提示。

最终交付需列出修改文件、真实接通项、mock 项、测试结果、未解决限制与本地预览地址。真实付费链路未验证时明确说明，不能把静态通过描述成视频生成已验收。
