## 2. 产品定位：已确认

面向成年用户的现代 AI 视频、图片创作平台。一个核心创作者或主角，能够持续创建、管理、发展多个成年角色；角色各有身份、外观、性格、服装、故事线与关系设定，形成可扩展的私人 AI 影像宇宙。

## 7. 功能讨论：建议草案，尚未冻结 PRD

主路径建议：选角色 → 图片/视频生成 → 调整结果 → 继续同一故事。

候选模块：

1. 创作工作台：一体化描述、参考素材、角色、模型、参数、费用展示。
2. 我的角色：成年身份、形象参考、外观性格、服装预设、多角色出演。
3. 连续创作：沿用上轮设定、参数回填、图生视频、结果再创作。
4. 作品与任务：状态、重试、历史、收藏、下载、素材管理。
5. 故事项目：角色与作品归组、关系和场景设定、片段整理。

建议角色身份与“本次出演造型”分离；每次任务保存实际配置快照，避免角色资料更新导致旧作品失去可追溯性。

建议默认私密、公开分享独立操作；具体权限与发布规则尚未定稿。

文生视频、首尾帧、延长、音频不能由“ComfyUI 有图生视频”自动推导支持；需分别核对模型/工作流。

首页优先直接创作还是角色大厅尚未确认。前一轮建议直接创作，旁边展示可选角色，用户随后转向技术栈讨论。

## 8. 技术方向

### 用户明确偏好

用户熟悉 Golang，询问 AI 改现有代码还是 Go 重写，不考虑成本，JS 仅作参考。

### 上一轮推荐方案（尚无实际代码，用户未单独冻结所有选型）

- 保留 Nuxt/Vue/TypeScript 前端。
- Go 重新实现业务后端，以 PeachArt 业务行为与契约作参考，不逐行翻译 TS。
- Go 模块化单体，按账户、生成、素材、角色、钱包划分；API 与 Worker 可共用模块，独立进程部署。
- PostgreSQL 为业务持久化；S3 兼容对象存储保存媒体。
- ComfyUI 和其他供应商通过后端适配，浏览器不直接持有服务端密钥。
- OpenAPI 生成前端请求与类型是推荐契约方案。此前 tRPC 复用建议属于 TS 后端路线，不能同时混成两套默认契约。
- Go Web 框架、数据库访问库、队列、实时状态传输、身份认证和部署方式尚未选定。
- Nuxt 中是否使用轻量 BFF 尚未决定；避免 Nuxt 和 Go 各自实现一套业务规则。

### 建议第一个端到端验收场景

不要无验证照搬 PeachArt 的模型价格、模型名单或成人内容适用性。后台存在某模型不代表允许所有内容类型。
