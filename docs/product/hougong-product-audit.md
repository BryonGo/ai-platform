## 评审基线（旅程视角的断点图）

```
① 发现（首页/探索/TV/技能）
② 表达（输入器：描述/参考图/画幅/模型/时长）

## A. 资产生命周期（对应 D2+D3，产品最伤的一段）

### A.0 判定（已更正）

原判「现状只有 `origin` 与 `hidden`、没有 scope 语义」**与当前代码不符**：工作区已落
`AssetItem.scope = temp|permanent`、`listAssets({ scope })`、`POST /platform/asset/{id}/save`
（幂等置 permanent），/assets 也已是**四页签**（我的资产/临时资产/演员库/回收站）。
依据：`useHougongApi.ts` L1025/L1087、`assets.vue` L17-33/L308、`tool/[code].vue` L138。

因此本段剩下的真实缺口是：
- 「保存」只铺到 /assets 临时页签与 /tool 结果区，**对话产物面板 `HgAssetPanel`、画布产物预览仍无入口**；
- 没有 `expires_at`/`saved_at`：临时产物不会到期清理，「临时」只是标签；
- 回收站仍是空壳（硬删、无恢复/彻底删除）、无详情/引用保护。

结论：**「前后端一起给 scope」这一步已经做了**；现在的重点是补 expires/清理、把保存入口铺满、以及回收站三动作。

### A.1 目标态

```
/assets      页签：我的资产 | 临时资产 | 演员库 | 回收站        ✅ 已落地（assets.vue 四页签）
字段         asset_scope(temp|permanent) + expires_at + saved_at
             ✅ scope 已有；❌ expires_at / saved_at 仍缺
             source_type(upload|tool|chat|canvas|edit) + source_id + task_id   ❌ 未接
默认规则     生成成功 → temp（7 天）；上传 → permanent；被引用 → 自动 permanent；保存 → permanent
             ⚠️ temp/permanent 与「保存→permanent」已有；「7 天到期」「被引用自动 permanent」未实现
清理         到期后台任务清 temp（含对象存储）；到期前 48h 出一次通知                ❌ 未实现
删除语义     回收站=软删（可恢复 30 天）→ 彻底删除；界面文案同步改                ❌ 仍硬删
引用保护     删除/彻底删除前列出引用（作品封面/角色封面/画布/历史任务/已发布），
             ≥1 个引用时给「仍要删除/先取消引用」选择                          ❌ 未实现
```

要点与上轮分析一致，补充三条线上实测后的约束：

1. **media 地址换代**：所有 3600s 签名相关的新 UI（详情抽屉、保存 confirmation）必须继续走
   `useMediaRefresh` 自愈，不允许出现新一处直读 URL 的旁路。
2. **保存动作 = 改状态，不重传不重算**：前端只调 `POST /platform/asset/{id}/save`，产物区按钮
   三态（临时资产 → 保存中 → 已保存）。落点：`tool/[code].vue` 结果区（✅ 已落地，`saveOutputs` L138）、
   `assets.vue` 临时页签（✅ 已落地，`saveToLibrary` L308）、`create.vue` 产物面板（HgAssetPanel）
   与画布产物预览（❌ 仍缺）。
3. **自动转永久的锚点**：被 `createWork` 收编为作品封面/内容、被 `setCharacterCover` 设为角色
   封面、被画布产物引用时，后端把 scope 转 permanent 并通知前端（一次性事件，不需要轮询 UI）。

### A.2 API 契约（新增）

```

前端同步项：`useHougongApi` 加方法（✅ `saveAsset`）、`/assets` 页签型组件（✅ 临时页签）、
`HgAssetPanel` 按钮态（❌ 待补）、`assets.vue` 的确认文案从「不可撤销」改为「可从回收站恢复」（❌ 待补，仍写「此操作不可撤销」）。

## B. 钱与账（对应 D1+D9）

**目标口径（仅供参考，待产品和后端最终拍板）**：金币单一口径 + 报价预检。
- 语义**已定**（2026-09-23，见仓库 AGENTS.md 踩坑 §2）：全环境统一 `coin_wallet`，`coinsPerCent=10`，
  1 元 = 100 分 = 1000 金币；旧 `credit_wallet` + `platform_balance_wallet` 已并入。
  前端**完全没有「金币」字样**，需要收敛的正是三处旧文案：顶栏「N 积分」（`app.vue` L510）、
  钱包页「可用积分 / 余额（元）」双卡片（`wallet.vue` L238-258）、充值换算「10 元 = 100,000 积分」（`wallet.vue` L298）。
- 支付网关是最高优先级缺口之一：用户旅程在充值收尾处是硬断点（`wallet.vue` 结算桩自述「支付网关接入后即可完成付款」）。
- 报价三处统一到一个取数函数（useModelCatalog），tool 页接入同一套（tool 页现 `cost` 恒 0）。
- 前置校验：发送前按当前选择（模型+画幅+时长+张数）预估费用，余额不够直接禁用发送按钮并提示差多少+去充值直达，而不是提交后再撤。
- 失败自动退款策略明确写进 UI（如「失败自动退回，最迟 X 分钟到账」），并在 ledger 有类型过滤。
- **会员口径已定（2026-09，已落地）**：仅按面值兑换金币（1 元 = 1000 金币），¥29/69/128/328/648
  → 29,000/69,000/128,000/328,000/648,000 金币，会员 1 个月；**不保留额外赠送、不保留余额奖励**。
  后端两种历史 choice（moreCredits/moreBalance）新下单同额、旧订单原样可读；前台只保留标准版单按钮，
  展示「¥69 → 69,000 金币 · 会员 1 个月」，不再做「更多积分/更多余额」二选一。
- **文本押金口径已定（2026-09，已落地）**：站点**未配置即 0 分**（建单侧兜最小 1 分保护），
  不得改成默认 100 分；显式配 0 同样 0。后台展示亦已收口（2026-09-24）：文本押金项
  `Default: "0"` + `allowZero: true`，页面显示 0、保存 0 合法，不再出现"页面显示 100、一保存
  就从零押金变 100 分"的误导；只有配置读取故障才用兜底值。

## C. 登录与身份（对应 D8）
