# AI Platform 产品定位与新手创作体验优化方案

[打开 HTML 交互方案](./index.html)

评审日期：2026-09-21。本文是基于前端代码审阅形成的**拟议产品方案**，不是当前已实现功能的使用说明。

本轮仅分析前端页面、组件与前端状态逻辑，未查阅后端实现，未执行真实注册、生成、上传、发布或支付。本文与同目录 HTML 均为评审材料，不修改业务代码。HTML 是概念交互原型：不调用 API，不上传真实文件，不存储或发送认证信息；其中示例输入与状态演示不代表线上数据、实际任务或实际计费。

## 1. 产品定位与改版目标

### 1.1 对用户的一句话说明

> 把你的想象变成图片和视频，和大家分享你的创作。

辅助说明：

> 说出想法，AI 创作助手带你完成。也可以从喜欢的作品开始，做出自己的版本。

产品应让初次使用者首先理解三个动作：**我来描述 → AI 帮我生成 → 我来修改和分享**。AI Agent 在界面中统一称为“AI 创作助手”。技术名词可在帮助说明中解释，不要求用户先理解模型、工作流、节点和参数才能开始。

产品定位包含两条相互衔接的路径：

| 路径 | 用户目的 | 完成标志 |
| --- | --- | --- |
| 自己创作 | 从描述或自己提供的素材开始，获得图片或视频 | 看到可预览、可继续修改、可下载的真实成果 |
| 发现与分享 | 发现他人的公开作品，了解做法，分享自己的成果 | 自主决定发布范围，明确哪些内容被公开 |

目前前端元信息定位为“个人创作者的 AI 图片与视频生产平台”，已有生成、素材、发布、探索等入口。优化重点是把现有能力整理为一条用户能够理解的旅程，不在前台暴露内部记录与接口的分工。

### 1.2 AI 助手的可感知工作方式

用简短的任务摘要解释 AI 将做什么，例如：“根据你的描述生成 1 张竖版图片，参考图用于保持颜色与构图。”用户可修改摘要后再确认。

只有真实实现的步骤才显示为进行中：参数校验可写“检查输入”，任务排队可写“等待生成”，真实生成可写“正在生成”。不要把前端动画写成“AI 正在分析”“AI 已规划”来暗示不存在的 Agent 能力。

若增加“帮我完善描述”，必须说明 AI 改了什么，允许用户保留原文。正式接入前，只提供明确标为“示例描述”的内容，不能将固定模板伪装成 AI 理解结果。

### 1.3 建议导航

- **开始创作**：图片、视频与自由描述的统一入口。
- **玩法工具**：对应 `/effects`，按目标选择，再分步完成。
- **发现作品**：浏览真实公开内容，查看作者与公开的创作方法。
- **我的作品**：管理自己的生成结果、草稿与发布状态。
- **素材**：管理上传图片、视频与可复用参考资料。

画布保留为进阶创作入口。本轮不调整画布业务流程，也不覆盖用户已经修改的其他模块。

## 2. 从首次访问到分享的用户旅程

| 阶段 | 用户最关心的问题 | 界面需要给出的答案 | 主操作 |
| --- | --- | --- | --- |
| 首次访问 | 这是做什么的，我会不会用？ | 一句话定位、图片/视频选择、可点击示例描述、三步说明 | 开始创作 |
| 输入想法 | 我应该写什么，必须传图吗？ | 场景化占位文字、明确的必填/选填标签、图片用途说明 | 下一步：确认生成 |
| 登录或注册 | 登录以后会不会丢内容？ | 当前输入在本页面保留；成功后回到原步骤 | 注册并继续 / 登录并继续 |
| 确认生成 | 将生成什么，会花多少？ | 输入摘要、产物规格、真实报价、默认私密说明 | 确认生成 · 实际报价 |
| 等待结果 | 是否成功提交，能否离开？ | 已提交/排队/生成状态、任务记录位置、真实进度 | 查看任务 / 在支持时取消 |
| 查看成果 | 如何修改和保存？ | 正确媒体预览、私密标识、可操作结果 | 继续修改 / 下载 / 分享作品 |
| 分享发布 | 别人会看到什么？ | 所选成果、标题、简介、可见范围的公开预览 | 发布到社区 |
| 再次创作 | 能否接着做或做同款？ | 来源与继承设置说明，保留用户修改空间 | 使用这个玩法 / 继续修改 |

首次引导做成可跳过的三个短提示，不强制用户看完整教程。熟悉产品后，用户可以直接使用之前的设置；确认提交和收费的行为保持一致。

## 3. 登录注册：减少进入门槛，保护创作连续性

### 3.1 已确认的前端问题

| 现状 | 体验影响 | 修改要求 |
| --- | --- | --- |
| 顶栏“登录”“注册”调用同一弹窗；弹窗打开时始终切到登录 | 点注册后仍需找注册页签 | 入口明确传入登录/注册模式，按钮含义与打开内容一致 |
| 独立注册页有密码规则与协议勾选，弹窗注册只判断非空 | 同一账号操作出现两套规则 | 共用校验与文案，字段附近显示密码要求 |
| 忘记密码、服务条款、隐私政策指向 `#` | 看起来能点，实际无有效结果 | 接入真实页面/流程；未实现前不提供假交互 |
| 独立登录与注册成功都跳首页 | 从工具或作品进入后，回不到原操作 | 保存来源路由与待继续动作，成功后原位恢复 |
| 草稿传递仅在内存中，提示却写“草稿已保留” | 用户可能误以为刷新、关闭后也能恢复 | 文案与实际保存能力一致，逐步完善持久草稿 |
| 独立登录有“记住登录”，前端提交未使用该选项 | 无法理解勾选是否生效 | 实现可验证的会话差异，或移除无实际作用的选项 |

### 3.2 目标流程

1. 游客可以选择创作类型、编辑描述并准备输入。
2. 点击“下一步”时需要认证，弹窗保留当前上下文，标题使用“登录后继续创作”或“登录后继续发布”。
3. 点击“注册”直接打开注册模式；邮箱与密码为主要字段，不要求先填写昵称、头像和偏好。
4. 成功后关闭弹窗，回到“确认生成”或“发布预览”；不自动创建收费任务。
5. 取消登录回到原编辑内容。刷新后不能恢复的本地文件，必须如实说明，不能显示“全部已保存”。

建议文案：

- 注册标题：“创建账号，开始你的第一件作品”。
- 登录说明：“登录后继续刚才的创作”。
- 当前页面保存：“当前输入已在本页面保留”。
- 登录成功：“已登录，确认内容和费用后即可生成”。
- 密码要求：“至少 8 位，包含字母和数字”。

注册赠送积分、费用减免、资料保留期限等信息只能使用真实规则，不能把页面现有常量当作永久承诺。移除“当前登录态：未登录”等内部状态说明。

### 3.3 表单响应

字段错误贴近字段展示，不只在表单底部显示一个通用错误。提交时按钮显示“登录中…”或“创建账号中…”，避免重复请求。失败保留邮箱与可继续操作的表单；网络错误与账号错误分别说明。弹窗支持键盘操作、焦点约束、关闭后返回原触发按钮。

## 4. 图片创作输入框：让用户知道写什么、图片起什么作用

### 4.1 现状与目标

首页与 `/create` 已共用 `HgChatComposer`，这是应保留的基础。当前占位内容主要解释 `@` 引用图片，主按钮叫“发送”，而首页实际先交接草稿，对话页则可能创建收费任务。相似外观下的行为差异容易造成误解。

新手输入区建议按下列顺序排列：

1. “图片创作 / 视频创作”模式选择。
2. 一句短说明：“描述想要的画面，不需要了解提示词”。
3. 宽文本输入框，旁边提供有文字的“添加参考图（选填）”。
4. 两到三个“试试这样描述”的示例，可填入后修改，不自动提交。
5. 简要设置摘要：“竖版 · 标准清晰度 · 1 张”，以及“更多设置”。
6. 主按钮、真实费用状态及私密说明。

图片占位文字示例：

> 你想画什么？例如：一间雨后的街角书店，暖黄色灯光，电影感，竖版。

参考图说明：

> 可以添加参考图，告诉 AI 你想参考人物、构图、色彩还是风格。

这些例子是输入帮助，不应展示为社区作品或历史创作。

### 4.2 必须落实的交互细节

- 纯文字生成图片不要求上传图；需要图片的工具必须在选择时明确标“需要 1 张图片”等要求。
- 参考图缩略图显示文件名、上传/就绪/失败状态与删除入口。删除被引用的图时提示具体引用，不悄悄改变原描述的含义。
- `@` 引用作为进阶快捷方式保留，先让用户理解“参考图”再解释快捷符号。
- 模型使用真实可用的推荐默认值，首屏以“推荐方案”呈现并可查看具体模型；高级设置不成为新手必答题。
- 参数变化后同步更新规格和报价；不支持的规格明确说明原因，不让用户提交后才收到能力不支持的错误。
- 首页用“下一步：确认生成”，实际创建任务的按钮用“确认生成”；不用“发送”同时代表聊天、页面跳转和收费任务。
- 用户已经输入内容时，示例描述采用插入/替换选择，避免无提示覆盖。

## 5. 视频创作输入框：先讲清生成路径，再讲镜头描述

### 5.1 现有能力边界不能混写

前端中存在两条不同的视频路径：

| 路径 | 已看到的前端行为 | 本次方案的处理 |
| --- | --- | --- |
| 对话创作的视频模式 | 提交时要求首帧图片；缺图会报“视频生成请先上传首帧图片” | 当前默认按“图片动起来”引导，不承诺只写文字即可生成 |
| `/tool/[code]` 视频工具 | 根据工具输入要求选择图生视频 `i2v` 或文生视频 `t2v` | 由真实目录能力决定展示“图片动起来”或“文字生成视频” |

不能因为工具页有文生视频分支，就把对话创作的所有视频模式统一写成“图片可选”。也不能反过来要求所有视频工具上传图片。

### 5.2 新手流程与文案

默认“图片动起来”的流程：

1. **选择起始画面**：上传图片或从自己的素材中选择。解释“这张图是视频开始时的画面”。
2. **描述怎么动**：主体动作、镜头移动、氛围变化；保留可跳过的示例帮助。
3. **确认视频规格**：显示真实支持的时长、画幅、清晰度和费用。
4. **生成并查看**：真实任务进度，完成后使用带播放控制的视频预览。

描述示例：

> 让画面中的树叶轻轻摆动，镜头缓慢向前，保持人物外观不变。

文生视频工具的描述示例：

> 描述一段短片：谁在什么地方，做什么动作，镜头怎样移动。

无首帧图片时就显示“先添加起始图片”，并让焦点转到图片入口，避免提交后才失败。只有当前工具目录明确支持文字输入时才显示文生视频路径。

### 5.3 输入角色与切换保护

- 首帧缩略图标为“起始画面”；额外图片标为“参考图 1/2”，说明真实支持的用途。
- 若要提供“结束画面”，先验证对应模型与工具确实支持，不把普通参考图误标为尾帧。
- 从图片切到视频时保留可兼容的内容，说明“第一张图将作为起始画面”；不兼容项提醒用户选择，不静默丢弃。
- 视频切换后展示当前时长，不能只显示画幅和分辨率，让用户直到计费时才知道生成几秒。
- 时长和数量变化重新取可用报价。没有真实估时能力时显示“正在生成，可在我的作品中查看进度”，不编造倒计时。

## 6. “创建你自己的 AI 幻想”模块：明确收益与隐私边界

### 6.1 模块定位

该模块承担进入玩法工具的引导，应直接说明用户可做什么、需要准备什么、完成后得到什么。本轮围绕通用图片与视频创作，不针对特定内容类别设计玩法。

推荐标题：

> 把你的想象，变成一件作品。

副标题：

> 选一个玩法，添加素材或描述，AI 帮你完成。满意后再决定是否分享。

主按钮：“选择一个玩法”。辅助入口：“了解创作步骤”。主按钮进入目标选择区，不自动挑目录第一项替用户做决定。

### 6.2 精确替换提示文案

当前文案“所有生成内容仅你可见”与已有发布入口难以同时解释。推荐统一为：

> 仅上传你拥有或已获得明确授权的图片。生成作品默认仅自己可见；完成后，你可以自主选择是否分享或发布到社区。

这是一条拟议的产品承诺，上线前必须核验默认可见性契约。若默认私密尚未被实际服务保证，先补齐行为再发布该文案。

分层放置：

- 上传区：“仅上传你拥有或已获明确授权的图片”。
- 生成按钮附近：锁图标 + “默认仅自己可见”。
- 发布确认区：“发布后，其他用户将看到你选择的作品、标题与简介”。

原始上传素材、提示词与参数是否公开，必须分别呈现并取得用户选择。不能未经能力核验就承诺“原图永不公开”“全部自动删除”“不存储”。当前横幅中的“图像自动删除”“无存储”等绝对表述，应先替换为可被当前能力验证的操作说明，例如“确认后生成”“完成后预览”，待保留策略与公开范围确定后再展示隐私承诺。

## 7. `/effects`：从目录页变为可回退的四步创作引导

目录浏览仍然保留搜索、类型与标签；新用户获得清晰的四步说明。熟悉产品的用户可从卡片直接开始，但进入后仍能看到当前位置与必要输入。

### 第 1 步：选择你想做什么

提问：“你想得到什么效果？”

- 按结果目标解释工具，例如“从文字生成图片”“让图片动起来”“调整图片效果”；具体选项由真实目录决定。
- 每张卡片展示：名称、一句话作用、需要准备的输入、将得到的结果、受支持时的真实费用信息。
- 主操作统一为“使用这个玩法”。工具预览明确标“效果示例”，不能被误认成当前用户生成结果。
- 选择后保留工具和玩法标识，显示“已选择”，进入下一步。
- 顶部不把目录第一项自动标为“新工具”；“新”应来自真实发布时间/标识，否则改为“推荐工具”。

### 第 2 步：准备素材或描述

提问：“这次创作需要什么？”

- 文字输入、单张图片、多张图片等布局由工具的真实输入要求决定。
- 每个位置写清“必填/选填”和用途，不只显示一个加号。
- 显示支持格式、数量、体积限制；这些数值来自真实限制，原型不假定统一上限。
- 可用“上传文件”和“从我的素材选择”两个明确入口。
- 用户点击“下一步”时逐项校验，错误定位到相关输入。

### 第 3 步：确认效果与费用

提问：“按这些设置开始吗？”

展示所选玩法、输入摘要、结果类型与数量、视频时长、费用、当前余额及默认可见范围。默认折叠高级参数，让用户始终能看到主按钮。

主按钮：“确认生成 · {真实报价}”。报价未获取成功时显示“费用暂不可用，重试获取”，不能用固定积分代替。若报价过期或输入变化，重新确认受影响的报价；只有确认后的任务提交进入生成阶段。

### 第 4 步：查看成果，决定下一步

- 生成中显示真实阶段与任务位置，结果完成后保留原图/原视频与新结果的清晰区分。
- 图片完整预览；视频使用真正播放器，不把视频地址放进图片标签。
- 成功后的主要操作：“继续修改”“下载”“分享作品”。
- 失败后显示可理解的原因和保留输入的重试入口；因余额、缺图、目录不可用而未创建任务，不展示假任务卡。
- 已成功但预览获取失败，写“生成已完成，预览暂不可用”，提供“重新加载结果”；该操作不重新生成、不触发新费用。

四步之间支持返回。返回修改玩法时，仅清理真正不兼容的字段，提前解释；不要把用户重新送回空表单。移动端使用单列和底部操作区，顶部保持“第 N 步 / 共 4 步”，不强迫用户在长页中寻找下一步。

## 8. 统一按钮、状态与收费语义

### 8.1 按钮行为规范

| 操作 | 用户含义 | 反馈与约束 |
| --- | --- | --- |
| 下一步：确认生成 | 整理输入并进入确认 | 不创建收费任务，显示具体缺失项 |
| 确认生成 | 用当前输入创建一次生成任务 | 显示报价，提交期间禁用重复点击，成功展示任务 |
| 修改描述 | 返回输入编辑 | 保留已有内容，不隐式再次生成 |
| 再生成一个版本 | 创建新结果 | 明确新任务与费用，保留原版本 |
| 重试生成 | 失败后重新执行 | 区分重新提交与重新读取状态；新费用以真实规则确认 |
| 重新加载结果 | 获取已存在的产物 | 不创建任务，不重新收费 |
| 取消任务 | 请求停止当前任务 | 仅实际支持时显示，服务确认后才显示已取消 |
| 发布到社区 | 主动公开选中的作品 | 发布前预览可见内容，成功后展示公开状态 |
| 复制分享链接 | 分享已有可访问地址 | 仅在链接真实可用时启用，成功提示“链接已复制” |

主按钮有正常、悬停、按下、键盘聚焦、不可用、提交中、成功和失败反馈。建议普通主操作高度至少 44px，图标按钮点击区域不少于 44×44px。不可用原因使用可见文字，不能只放在鼠标悬停提示里。动画可短暂强化状态变化，不制造虚假的业务进度，并尊重系统减少动态效果设置。

### 8.2 状态规范

| 状态 | 推荐说明 | 可继续操作 |
| --- | --- | --- |
| 输入不完整 | “还需要 1 张起始图片” | 添加图片 |
| 上传中 | “正在上传第 1 张图片…” | 按实际能力取消上传 |
| 正在提交 | “正在创建生成任务…” | 避免重复提交 |
| 排队 | “已提交，正在等待生成” | 查看任务、支持时取消 |
| 生成中 | “正在生成视频” | 显示真实进度；未知时使用不确定进度动画 |
| 同步中断 | “状态更新暂时中断，正在重新连接” | 重新同步，不直接标生成失败 |
| 生成完成 | “作品已完成，当前仅自己可见” | 预览、修改、下载、分享 |
| 预览读取失败 | “已生成，暂时无法加载预览” | 重新加载结果 |
| 生成失败 | “生成未完成：{可理解原因}” | 修改输入、查看费用状态、重试 |

退款与任务状态分开显示。现有前端有失败时直接写“积分已退回”的情况，应只有获得实际结算确认后才显示“已退回”；未知时写“费用状态确认中”。报价为零与报价缺失必须分开处理，不能使用 `cost || 固定值` 覆盖真实零费用。

## 9. UGC：创作完成后自然进入分享

### 9.1 可见性与用户选择

目标是统一呈现“私密生成结果”和“社区发布”的关系，避免用户理解两套记录。

| 可见范围（拟议） | 解释文案 | 上线要求 |
| --- | --- | --- |
| 仅自己 | “保存在我的作品中，只有你能查看” | 核验实际权限与默认行为 |
| 链接分享 | “获得链接的人可以查看” | 有可用的公共路由、真实链接权限和撤销策略后开放 |
| 发布社区 | “展示在社区，其他用户可以发现你的作品” | 核验发布状态与公开内容范围 |

当前前端存在可见性选项和社区发布入口，但不能因此认定访客链接可访问、撤销即时生效或同款复用权限已具备。以上是能力待确认的目标方案。

### 9.2 发布体验

1. 生成结果中点击“分享作品”。
2. 选择具体成果，填写标题和选填简介；视频可选封面时需支持真实封面来源。
3. 预览将公开的内容。是否分享提示词、模型设置或允许做同款，应作为独立选项，不能藏在正文占位文字中默认公开。
4. 明确点击“发布到社区”。失败保留输入，成功显示“已发布”。
5. 提供“查看公开作品”“复制链接”“继续创作”；不可用的能力不显示为可点击按钮。

社区卡片展示真实作者、作品类型与玩法来源。“做同款”只继承作者允许公开的创作信息，并说明“你可以修改后生成自己的版本”；不会原封不动把原作者作品发布为自己的内容。权限能力尚未确认时只提供“查看玩法”，不声称可以复用原图或角色。

### 9.3 页面命名与入口修正

- 顶栏当前“发布作品”去 `/create`，应改为“开始创作”，或提供真正的选成果发布入口。
- 首页探索的“更多作品”应进入公共作品列表或展开当前探索流，不进入个人 `/works`。
- `/works` 对用户统一为“我的作品”，可通过“全部 / 草稿 / 已发布”管理，不展示“另一套记录”等内部术语。
- 无真实社区内容时展示明确空状态和“分享第一件作品”的引导，不补虚假作者、作品、点赞数或活跃数据。
- 游客能否浏览真实公开作品需核验接口。如果暂时不能，只说明产品支持创作和主动分享，不直接访问需要登录的个人数据来填补公开区。

### P2：基于实际能力逐步增强

- 真实公开社区浏览、稳定分享链接与撤销机制。
- 持久草稿与跨会话恢复，明确文件保存和删除策略。
- 经作者授权的同款复用、来源标记、创作者资料页。
- 基于真实能力的 AI 描述完善、创作建议与可解释摘要。
- 真实任务耗时统计与可信估时；用用户反馈优化引导，不先编造预测。

## 13. 验收清单

### 13.1 完整旅程

- [ ] 新用户能用一句话说出产品用途，并找到图片、视频、发现作品入口。
- [ ] 不理解“模型”“提示词”“Agent”的用户也能完成首件图片创作。
- [ ] 点注册直接出现注册；取消认证后原输入仍在。
- [ ] 登录成功回到原创作或发布位置，不自动生成、不自动扣费。
- [ ] 图片纯文本路径不错误要求上传图片。
- [ ] 对话视频在提交前说明需要起始图片；支持文生视频的工具按其真实要求运行。
- [ ] 图片/视频切换不静默清空资料，不给参考图赋予不存在的能力。
- [ ] `/effects` 用户能知道当前第几步、还缺什么，并可回退修改。
- [ ] 生成前明确结果规格、费用与默认可见范围。
- [ ] 成功结果可正确预览并找到修改、下载、分享操作。
- [ ] 发布前能确认哪些内容公开；取消发布不会把私密内容公开。

### 13.2 异常与状态

- [ ] 报价失败、免费报价、余额不足各有准确提示，不显示编造的固定价格。
- [ ] 重复点击仅创建预期任务；重复生成有新任务/费用说明。
- [ ] 网络断开不直接伪装为任务失败；恢复后同步真实状态。
- [ ] 已生成但预览失败，可以只重新读取成果，不重新计费。
- [ ] 未取得结算确认，不显示“积分已退回”。
- [ ] 上传失败、生成失败、发布失败保留可恢复的用户输入。
- [ ] 所有“更多”“发布”“忘记密码”“协议”入口均到达对应真实内容。
- [ ] 未登录访问分享链接、私密访问限制与撤销后的行为经过真实能力验证。

### 13.3 UI 与可访问性

- [ ] 主操作使用可理解的文字，图标按钮有可访问名称和足够点击面积。
- [ ] 仅用键盘可完成模式选择、表单、弹窗与四步引导。
- [ ] 禁用原因可见，错误靠近对应输入，动态状态可被辅助技术感知。
- [ ] 移动端输入、错误提示与底部主按钮不会互相遮挡。
- [ ] 动画不表示虚假任务进度，减少动态效果设置受到尊重。
- [ ] 私密/公开状态来自实际状态，不出现写死“默认私密”与公开结果并存的矛盾。

### 13.4 评审原型边界

- [ ] HTML 清楚标记“概念交互原型”，演示状态不被误认为真实任务。
- [ ] HTML 不调用生产 API，不发起上传，不收集或存储邮箱、密码或其他认证信息。
- [ ] 示例只用于说明布局和输入方式，不伪造社区作品、作者、点赞或用户历史。
- [ ] 尚未确认的分享、复用、退款和保存能力在方案中明确标为待确认。

## 14. 建议的评审与实施顺序

先确认产品定位、认证后续接、图片/视频输入要求与费用语义，再确认 `/effects` 四步布局与私密/发布文案。P0 实施验收通过后推进 P1 页面整合；依赖新接口或权限契约的 P2 能力单独验证，不以概念原型替代真实支持。

建议使用一名首次接触产品的测试者进行任务验收：让其从描述一个画面开始，经注册、费用确认、等待、预览、修改、主动发布完成全流程。记录卡住的步骤、返回修改次数和任务失败原因，优先解决实际阻碍，不以新增更多入口作为优化完成的标准。
